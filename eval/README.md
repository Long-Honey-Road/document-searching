# Прогон качества RegAgent

На локальном тестовом стенде нужны первая редакция мини-корпуса, настроенная модель и учётки `employee_public` и `employee_fin`. Скрипт очищает память этих учёток перед указанными кейсами и создаёт диалоги. Используйте стенд, где эти учётки свободны. [Подготовка стенда](../deploy/README.md)

```bash
uv run python -m scripts.eval.run --validate-only
uv run python -m scripts.eval.run --env-file .env --stand http://localhost:8080
```

`--manifest` указывает на манифест корпуса, развернутого на стенде. По умолчанию используется `data/docs/manifest.yaml`. `--reports-dir` меняет расположение результатов. Кейс `margin-after` сохранён для e2e смены редакции. Автоматический прогон оценивает 37 кейсов.

JSONL записывается по мере получения ответов. Отчёт включает сводку, медиану и p90, провалы и предполагаемых владельцев. Утечка источника останавливает прогон сразу. Коды завершения — `0` все проверки прошли, `1` есть провалы, `2` ошибка конфигурации или соединения, `3` обнаружена утечка.

## Разметка и разбор

Возьмите 20 ответов из `eval/reports/raw/<дата>.jsonl`, включая разные типы вопросов и провалы. В каждой выбранной строке замените `"review": null` на объект с полями `semantic_match` и `claims_supported`, заполнив оба значениями `true` или `false`. Сверьте смысл с `question.reference_answer`, а утверждения — с пунктами документов, на которые ссылается ответ. `review.note` позволяет зафиксировать расхождение. Если причина провала выяснилась при разборе, укажите её в `diagnosis.cause` и поставьте `knowledge` или `backend` в `diagnosis.owner`.

Пересоберите отчёт после разметки тем же именем файла:

```bash
uv run python -m scripts.eval.run --report-from eval/reports/raw/<дата>.jsonl
```
