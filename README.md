# RegAgent — агент по корпоративным регламентам

Расчёт стоимости запросов для модели **qwen3.8-flash-next** лежит в [Excel-файле](docs/regagent-qwen-cost.xlsx).

Сотрудник задаёт вопрос обычным языком и получает короткий ответ со ссылками на конкретные пункты регламентов. Агент учитывает область бизнеса, пояснения отдела контроля качества (ОКК) и права доступа к документам. Если в регламентах ответа нет, он прямо об этом говорит и предлагает передать вопрос в ОКК. Опубликованное пояснение ОКК становится частью базы знаний.

**Проблема.** Регламентов много, они ссылаются друг на друга, расходятся между подразделениями и меняются. Часть документов закрыта для большинства сотрудников. Обычный поиск или чат-бот на LLM либо не находит нужный пункт, либо отвечает уверенно и без опоры на документ.

**Как решено.** Основа — графовый RAG на LightRAG и OKF, git-хранилище регламентов, разобранных на пункты. LightRAG находит связанные пункты по смыслу и через граф сущностей, в том числе в разных документах. OKF хранит точный текст каждого пункта каждой редакции. Ответ строится только из фрагментов, полученных в этом запуске, и это проверяет код. Вокруг этого:

- **Фрагмент равен пункту регламента.** У каждого фрагмента служебный заголовок с документом, редакцией, пунктом, областью и уровнем доступа. Отсюда ссылки до пункта и проверка прав на каждом фрагменте.
- **Отдельный индекс и граф на каждый уровень доступа.** Плюс повторная сверка каждого фрагмента с реестром документов и документы-канарейки для обнаружения утечек.
- **Проверка ответа кодом.** Каждая ссылка должна вести на фрагмент из этого запуска. Ответ по нескольким областям и сомнительный вывод дополнительно сверяет модель. Неподтверждённый ответ не публикуется.
- **Практика ОКК как фрагмент того же уровня доступа**, с режимом «уточняет» или «заменяет» пункт. Если практика заменяет пункт, её обязательно цитируют.
- **Переиндексация по изменению файла.** Новая редакция заменяет старую в индексе, практика к изменённым пунктам уходит в ОКК на перепроверку.
- **Область и память.** Агент уточняет область, если порядок в подразделениях разный, и запоминает её по прямым указаниям пользователя.

## Возможности

| Возможность | Как выглядит |
| --- | --- |
| **Ответ со ссылками до пункта** | Короткий ответ, раскрываемый блок «Подробнее», карточки источников: документ, пункт, редакция. Номер ссылки в тексте кликабелен |
| **Ответ по нескольким документам** | Агент собирает ответ из связанных регламентов: поиск LightRAG в режиме `mix` (граф и векторы) и связи между документами по названиям |
| **Область бизнеса** | Если в ДИБ, ДБРЦТ и общих регламентах порядок разный, агент спрашивает область. В ответе всегда указано, по какой области он отвечал |
| **Память об области** | Агент запоминает область после 2 прямых указаний за 14 дней и меняет её после 3 указаний подряд на другую. Панель «Память» показывает текущую область, счёт и историю, там же её можно сбросить |
| **Разграничение доступа** | Документы закрытого уровня видны только участникам группы Keycloak. Для остальных их как будто нет |
| **Практика ОКК** | Пояснения ОКК к пунктам с режимом «уточняет» или «заменяет». В ответе карточка «Практика ОКК» и привязанный пункт |
| **Контур ОКК** | Кнопка «Передать в ОКК» у вопроса, с комментарием. «Мои заявки» со статусами. Для админа: очередь заявок, редактирование текста и привязок, «Принять и опубликовать» или «Отклонить», аналитика неотвеченных вопросов с группировкой и созданием заявки из группы, перепроверка практики при смене редакции документа |
| **Отказы** | Вопросы не по теме, просьбы посчитать за пользователя, попытки взломать промпт |
| **Переиндексация** | Добавление, изменение или удаление файла в папке корпуса подхватывается автоматически |
| **Наблюдаемость** | Структурированные события сервисов, учёт токенов по операциям, Grafana с дашбордом |

## Стек и модели

| Слой | Что используется |
| --- | --- |
| LLM | **Qwen3.8-Flash-Next** (125 млрд параметров) через OpenAI-совместимый API. Модель для ролей агента, классификатора, извлечения графа и ключевых слов можно задать отдельно |
| Эмбеддинги | **bge-m3** (размерность 1024) через Ollama. Альтернатива — Hugging Face Text Embeddings Inference |
| Реранк | По эмбеддингам bge-m3 (`RERANK_MODE=embeddings`) или отдельный **bge-reranker-v2-m3** на TEI (`RERANK_MODE=tei`) |
| Поиск и индекс | LightRAG 1.5 как библиотека: граф сущностей в Apache AGE, векторы в pgvector. Docling (DOCX → Markdown), pymorphy3 (лемматизация названий документов) |
| Агент | Aegra 0.12 (сервер Agent Protocol), LangGraph, Deep Agents, LangChain OpenAI |
| Сервисы | Python 3.12–3.13, uv, FastAPI, aio-pika |
| Хранилища | PostgreSQL 17 с pgvector и Apache AGE, RabbitMQ, git-репозиторий OKF |
| Вход | Keycloak 26 (OIDC, PKCE), группы — уровни доступа, роль `admin` для ОКК |
| Web | React 19, Vite, TypeScript, Tailwind, shadcn/ui, LangGraph SDK, oidc-client-ts |
| Инфраструктура | Docker Compose, Caddy, Cloudflare Tunnel. Мониторинг: Grafana, Loki, Grafana Alloy |

## Корпус документов

Демо-корпус лежит в [`data/demo_corpus`](data/demo_corpus). В нём 25 DOCX и `manifest.yaml`.

- **4 образца регламентов заказчика:** проектная деятельность ДБРЦТ, проектная деятельность ДИБ, пресейловая деятельность ДИБ, организация проектной деятельности.
- **21 синтетический регламент.** Это документы, на которые ссылаются образцы (подбор субподрядчика, контроль маржинальности), и типовые внутренние процессы: командировочные расходы, возврат лицензий, доступы, инциденты ИБ и другие. Тексты сгенерированы для демонстрации генератором [`scripts/synth`](scripts/synth/README.md) на основе образцов и `scripts/synth/expanded_regulations.json`.
- **Области:** ДИБ, ДБРЦТ и «общий». **Уровни доступа:** `public` (24 документа) и `closed_fin` (регламент архивирования финансовых заключений).
- **Вторая редакция** регламента контроля маржинальности (`--revision 2`) нужна для проверки переиндексации: срок проверки меняется с трёх рабочих дней на один.
- **Две записи практики ОКК** в [`data/practice_seeds.yaml`](data/practice_seeds.yaml): такси в командировке в выходной и срок назначения РП в ДИБ при неполной карточке проекта. Они публикуются обычным путём через заявку ОКК (см. [Развёртывание](#5-демо-практика-окк)).

Манифест задаёт для каждого файла `doc_id`, название, области, уровень доступа, редакцию и дату вступления в силу. Файл без записи в манифесте не индексируется.

## Как пользоваться

**Сотрудник:**
1. Войти и задать вопрос, например: «Дирекция ИБ. Кто и в какой срок назначает руководителя проекта?».
2. Ответ — короткий вывод, «Подробнее» и источники. Над ответом указана область. Нет области в вопросе и порядок в подразделениях разный — агент её спросит.
3. Если агент не нашёл подтверждения в регламентах, нажать «Передать в ОКК» у вопроса, добавить комментарий и подтвердить. Статус заявки — во вкладке «Мои заявки».
4. «Память» в колонке диалогов показывает, какую область агент помнит, и позволяет её сбросить. Сказать «запомни ДИБ» или «забудь область» тоже работает.

**Админ ОКК:**
1. «Очередь ОКК»: открыть заявку, написать или поправить текст пояснения, указать документ, редакцию и пункт для каждой привязки, выбрать режим «уточняет» или «заменяет», нажать «Принять и опубликовать».
2. Статус `published` появляется после индексации практики. Дальше агент цитирует её в ответах всем, у кого есть доступ к привязанным пунктам.
3. «Аналитика»: сводка за период, фильтры по области, исходу и статусу заявки, группы похожих неотвеченных вопросов с числом повторов. Из группы можно создать заявку.

## Развёртывание

Всё поднимается одним Docker Compose: Postgres (pgvector + AGE), RabbitMQ, Keycloak с готовым realm, knowledge, backend, web, Caddy. LLM в состав не входит, это внешний OpenAI-совместимый адрес.

### 1. Требования

- Docker с Compose v2, [uv](https://docs.astral.sh/uv/).
- OpenAI-совместимый адрес LLM и ключ.
- Эмбеддинги — один из вариантов:
  - Ollama на хосте с моделью `bge-m3` (`ollama pull bge-m3`). Контейнеры ходят к ней по `host.docker.internal:11434`. На Linux Ollama должна слушать не только loopback (`OLLAMA_HOST=0.0.0.0`), а порт 11434 надо закрыть снаружи;
  - TEI в Compose: профиль `local-embeddings`, `EMBEDDINGS_BASE_URL=http://embeddings:80`, модель Hugging Face в `EMBEDDINGS_MODEL`. На Apple Silicon — `TEI_IMAGE=ghcr.io/huggingface/text-embeddings-inference:cpu-arm64-1.10`.
- При сборке нужен интернет: PyPI, Docker Hub, quay.io, ghcr.io, github.com (исходники AGE), словарь tiktoken.

### 2. Конфигурация

```bash
cp .env.example .env
```

В `.env` заполнить:
- `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`;
- все значения `change-me` и `replace-me`: пароли БД, RabbitMQ (и внутри `RABBITMQ_URL`), Keycloak, демо-учёток, `KNOWLEDGE_INTERNAL_TOKEN`;
- для внешнего адреса — `PUBLIC_BASE_URL`, `KEYCLOAK_ISSUER` и `VITE_OIDC_AUTHORITY`. По умолчанию это `http://localhost:8080`.

Полный список переменных — в [LLD, «Переменные окружения»](docs/LLD.md#11-переменные-окружения). Пароли демо-учёток применяются только при первом старте Keycloak.

### 3. Корпус и запуск

```bash
uv sync --all-packages --frozen
uv run python scripts/synth/generate.py      # корпус в data/docs: 25 документов + manifest.yaml
docker compose --env-file .env -f deploy/compose.yaml up -d --build
docker compose --env-file .env -f deploy/compose.yaml ps
```

Приложение откроется на <http://localhost:8080>. Knowledge сам замечает документы в `data/docs` и индексирует их. Это занимает время: на каждый документ уходит несколько вызовов LLM для извлечения графа.

### 4. Проверка индексации

```bash
docker compose --env-file .env -f deploy/compose.yaml exec postgres \
  psql -U postgres -d knowledge -c "SELECT status, count(*) FROM documents GROUP BY status"
```

Готово, когда все документы в `indexed`. Упавшие документы ставятся заново так:

```bash
docker compose --env-file .env -f deploy/compose.yaml exec knowledge python -m regagent_knowledge.reindex --failed
```

### 5. Демо-практика ОКК

После индексации корпуса (документы `business-travel-expenses` и `dib-project-activity` должны быть в `indexed`) две записи практики публикуются через обычный контур ОКК. Скрипт входит как `employee_public`, создаёт заявки и публикует их как `admin`. Пароли он берёт из `.env`. Повторный запуск новых заявок не создаёт.

```bash
echo 'REGAGENT_ORIGIN_PORT=8080' >> .env      # порт Caddy на loopback
uv run python -m scripts.synth.publish_demo_practice --check
uv run python -m scripts.synth.publish_demo_practice --root .
```

Скрипт ждёт индексации каждой записи до 15 минут. Для этого должна работать модель эмбеддингов.

### 6. Переиндексация и обновление корпуса

- **Изменить документ** — заменить DOCX в `data/docs` и поднять `version` в манифесте. Старая редакция выйдет из поиска, практика к изменённым пунктам уйдёт в ОКК на перепроверку.
- **Проверить на демо-корпусе:** `uv run python scripts/synth/generate.py --revision 2` при работающем стенде.
- **Пересобрать весь индекс** (например, после смены модели извлечения): `docker compose … exec knowledge python -m regagent_knowledge.reindex --all`.

### Частые проблемы

| Симптом | Что сделать |
| --- | --- |
| Сборка knowledge падает на `lightrag-download-cache` | Нет доступа к `openaipublic.blob.core.windows.net` (словарь tiktoken). Шаг не отключать, иначе knowledge пойдёт в интернет при старте |
| Вход возвращает обратно, Keycloak ругается на redirect URI | Адрес в браузере не совпадает с `PUBLIC_BASE_URL`. Открывать ровно его |
| Пароли учёток не поменялись после правки `.env` | Realm импортируется только при первом старте. Менять через `kcadm.sh` в контейнере `keycloak` ([`deploy/keycloak/README.md`](deploy/keycloak/README.md)) |
| `host.docker.internal` недоступен из контейнера | Ollama должна слушать не только `127.0.0.1` |
| Документ не индексируется | Нет записи в манифесте или неизвестный уровень доступа. Статус и ошибка — в таблице `documents` (шаг 4) |
| TEI на Mac очень медленный | Не тот `TEI_IMAGE`, на Apple Silicon нужен `cpu-arm64-1.10` |

## Структура репозитория

```
packages/common/     общие контракты: фрагменты, уровни доступа, сообщения, события

tests/               межсервисные контракты, e2e, проверки документации
docs/                HLD, LLD, техдолг
```

## Тесты и прогон качества

```bash
uv run ruff check . && uv run mypy packages services
uv run pytest                      # unit, контракты, правила выкатки
uv run pytest -m integration       # с Postgres (AGE) и RabbitMQ, включая тесты на утечки
uv run pytest -m e2e               # сквозные сценарии на поднятом стенде
cd web && npm test
```

Прогон качества по контрольным вопросам и диалогам — `scripts/eval`, вопросы в `eval/questions.yaml` и `eval/behavior-dialogues.yaml`:

```bash
uv run python -m scripts.eval.run --env-file .env --stand http://localhost:8080
```

Прогон останавливается при первой утечке закрытого источника. Подробнее — в [LLD, «Тестирование»](docs/LLD.md#13-тестирование).
