# 09. Решения, изменения и открытые вопросы

Исходные документы: концепт и system design v2 (Claude Docs, 27.11.2026). Здесь — что из них взято, что изменено и почему.

| D-25 | Подключения LightRAG к Postgres — из переменных `POSTGRES_HOST/PORT/USER/PASSWORD/DATABASE` процесса; knowledge выставляет их из `KNOWLEDGE_DB_*` до инициализации. Нужен Python-пакет `pgvector` | принято (спайк P0-5) | так LightRAG читает конфиг (`ClientManager`, общий пул на процесс); без пакета `pgvector` LightRAG пытается доставить его сам во время работы |

В рабочем каталоге LightRAG хранит якорь конфигурации хранилищ; без постоянного тома проверка расхождения конфигурации при старте не выполняется |

## Изменения относительно концепта v2

1. **LightRAG по контейнеру на уровень → по объекту и workspace на уровень в одном сервисе** (D-02). Физическое разделение данных сохраняется (свои разделы таблиц и свой граф AGE на уровень), но нет N контейнеров и N админок. Из v2 уходит пункт про `/webui` LightRAG на каждом уровне: служебная страница строится на нашем API.
2. **Отдельные индексатор и сервис ОКК → `knowledge` и `backend`** (D-01, D-03). Модули внутри сохраняют те же границы, разнести можно позже.
3. **Быстрый путь на LangGraph + Deep Agents для глубокого режима → Deep Agents сразу** (D-04). Риск по скорости остаётся и закрывается замерами; Deep Agents 0.7 стал легче (из базового набора убран список задач). Guard и проверка ссылок — узлы графа, а не правила в промпте.
4. **vLLM и раздел «Модели, скорость и железо»** — не про нас: модель внешняя (D-05). Остаётся требование к серверу модели: вызов инструментов и ответ по JSON-схеме. Специфичные параметры (например отключение рассуждений) — через `LLM_EXTRA_BODY_JSON`.
5. **Чат на форке agent-chat-ui → свой React** (D-06).
6. **`access: [all]` списком → один уровень на документ** (D-08).
7. **Тесты на утечки дополнены** канарейками и проверкой при старте (D-12) — по итогам изучения изоляции workspace.
8. **Отдельные пользователи Postgres на БД** — LightRAG выполняет DDL при старте (создаёт расширения и таблицы), поэтому права владельца даём только на БД `knowledge`.
9. **Словарь терминов сокращён** до неочевидных.

## Последствия выбора Apache AGE

- Стоковый образ Postgres не подходит: нужен свой с pgvector и AGE; при выборе major-версии Postgres сверять, что AGE её поддерживает (AGE обычно отстаёт).
- Если у заказчика в будущем будет управляемый Postgres без AGE — либо их администраторы ставят расширение, либо графовое хранилище LightRAG меняется на другое (Neo4j и др.). Остальной код от этого не зависит: граф скрыт за LightRAG.
- LightRAG сам создаёт расширение и таблицы при старте — его пользователю БД нужны права владельца (только на свою БД).
