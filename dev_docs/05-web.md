# 05. Веб-интерфейс

Зафиксировано минимально: подробно дизайн сейчас не проектируем. Требование — простой, аккуратный, не вырвиглазный интерфейс.

## Стек

React + Vite + TypeScript, Tailwind CSS, shadcn/ui. Стриминг диалога — React-хуки LangGraph SDK к Aegra. Вход — OIDC с PKCE (`react-oidc-context` или аналог) к Keycloak. Сборка — статика, отдаёт Caddy.

## Страницы

| Страница | Кто видит | Что есть |
| --- | --- | --- |
| Чат | все | список диалогов, поток ответа, раскрываемый блок «подробнее», источники с переходом к карточке пункта в MVP, действие «Передать в ОКК» |
| Мои заявки | все | свои заявки и их статусы |
| Очередь ОКК | роль `admin` | заявки и перепроверки, редактирование, публикация и отклонение |
| Аналитика ОКК | роль `admin` | сводка, группы неотвеченных вопросов и создание заявки |
| Служебная | роль `admin` | статусы документов и задач индексации, повтор упавших, список «на сверку» |

## Правила

- Одна светлая тема, нейтральная палитра, один акцентный цвет; компоненты shadcn без кастомизации сверх нужного.
- Источники всегда видны под ответом; номер ссылки в тексте кликабелен.
- Ошибки и долгие операции показываются явно («ищу в регламентах…»), без зависших спиннеров.
- Никаких данных, кроме выданных backend; токен не хранится в localStorage.

### Первый выпуск ОКК (D-52…D-54)

В чате у вопроса есть «Передать в ОКК». Перед отправкой открывается форма подтверждения с необязательным комментарием. В «Моих заявках» сотрудник отслеживает статусы. Кабинет доступен администратору, проверившему права через backend. Эксперт выбирает заявку, вводит или правит текст, указывает документ, редакцию и пункт каждой привязки, выбирает режим и подтверждает публикацию или отклонение. В аналитике показаны итоги за период, фильтры, число повторов неотвеченных вопросов и создание заявки из группы.
